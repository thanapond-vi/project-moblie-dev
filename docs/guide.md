## 1. แอปนี้คืออะไร

| หัวข้อ | รายละเอียด |
|---|---|
| ปัญหา | อ่านแล้วจำไม่ได้ จับใจความไม่เป็น เพราะอ่านผ่านๆ และไม่ได้ทบทวน |
| วิธีแก้ | Active Recall: อ่านแบบจับเวลา → ปิดบทความ → เขียนสรุปจากความจำ → AI ตรวจว่าขาดประเด็นอะไร → ทบทวนซ้ำตามรอบ |
| ผู้ใช้ | นิสิต นักศึกษา และคนที่อยากฝึกอ่านจับใจความ (English / Chinese / Thai) |

## 2. ลำดับการใช้งาน

```text
เปิดแอป (โลโก้ + ไฟกะพริบ)
  → Login / สมัคร → ตั้งค่าเริ่มต้น 2 ขั้น (ครั้งแรก)
  → แท็บคลัง (Home) → เลือกหมวดหรือค้นหัวข้อ → สุ่มบทความจาก Wikipedia
  → อ่าน + จับเวลา (ฟังเสียงได้, พักไว้อ่านต่อได้)
  → เขียนสรุปจากความจำ → AI ให้คะแนน + บอกประเด็นที่ขาด + แนะนำแท็ก → บันทึก
  → วันถัดไป: แท็บทบทวน นึก → เฉลย → ให้คะแนนตัวเอง
  → แท็บสถิติ ดูความคืบหน้า
```

หน้าจอทั้งหมด:

| หน้า | ไฟล์ | หน้าที่ |
|---|---|---|
| เปิดแอป | `screens/launch_screen.dart` | ประกอบโลโก้, ไฟกะพริบพร้อมเสียง, แตะเพื่อข้าม |
| Login / สมัคร | `screens/auth_screen.dart` | อีเมล, Google, ลืมรหัสผ่าน |
| ตั้งค่าเริ่มต้น | `screens/onboarding_screen.dart` | ชื่อเล่น, รูป, ภาษา, เวลาอ่าน |
| โครงแท็บ | `screens/app_shell.dart` | เมนูล่าง 3 แท็บ: คลัง / ทบทวน / สถิติ |
| คลัง (Home) | `screens/home_screen.dart` | สถิติย่อ, สุ่มบทความ, อ่านค้าง, ประวัติ, ลบ |
| อ่าน | `screens/reading_screen.dart` | Timer, เสียงอ่าน, คำถามชวนนึก, บุ๊กมาร์ก |
| สรุป | `screens/summary_screen.dart` | เขียนสรุป, คะแนน AI, แท็ก, บันทึก/แก้ไข |
| ทบทวน | `screens/review_screen.dart`, `review_session_screen.dart` | รายการครบกำหนด, นึก → เฉลย → ให้คะแนน |
| สถิติ | `screens/stats_screen.dart` | กราฟเวลาอ่าน, คะแนน, ปฏิทิน, หมวด |
| โปรไฟล์ | `screens/profile_screen.dart` | ตั้งค่า, Logout, ลบบัญชี |

## 4. โครงสร้างโค้ด

```text
lib/
├── main.dart      เริ่มแอป: .env → Settings → Firebase → KeepApp → LaunchGate → AuthGate
├── core/          ของกลาง: theme, spacing, radius, motion, validators, config
├── models/        ข้อมูล: Article, StudyLog, ReadingSession, KeyPoint, ReviewSchedule, สถิติ
├── services/      คุยกับโลกภายนอก: Firebase, Groq, Wikipedia, TTS, SharedPreferences
├── screens/       หน้าจอ
├── widgets/       ชิ้นส่วนที่ใช้ซ้ำ: โลโก้, เมนูล่าง, กราฟ, ป้ายคะแนน
└── l10n/          ข้อความ 3 ภาษา (arb/) และโค้ดที่สร้างอัตโนมัติ (gen/)
test/              core · models · services · widgets · screens · live
```

**หลักการแบ่งชั้น:** `screens` → `services` → (Firebase / HTTP / SharedPreferences)

- หน้าจอไม่เรียก Firebase หรือ HTTP ตรงๆ
- service แปลง error ทุกชนิดเป็น `AppException` ที่มีข้อความตามภาษาแอปแล้ว หน้าจอจึง `catch` ชนิดเดียวแล้วแสดง SnackBar
- ในโค้ดมีคอมเมนต์ `// X มาจาก lib/...` บอกว่า class หรือฟังก์ชันจากไฟล์อื่นอยู่ที่ไหน ตามไปอ่านต่อได้

**State management:** `setState` + `StreamBuilder` (Firestore, Auth) + `ValueNotifier` (ค่าที่หลายหน้าใช้ร่วม เช่น ธีม ภาษา เซสชัน โปรไฟล์) ไม่ใช้ library เพิ่ม

**Navigation:**

```text
AppRestarter (เปลี่ยน Key = รีสตาร์ตแอป)
 └── KeepApp → MaterialApp
      └── LaunchGate → AuthGate
           ├── ไม่มี user → AuthScreen
           └── มี user → AppShell (คลัง / ทบทวน / สถิติ)
                ├── ผู้ใช้ใหม่ → OnboardingScreen (ปิดไม่ได้จนกว่าจะกดเริ่มใช้งาน)
                ├── ReadingScreen → pushReplacement → SummaryScreen
                ├── ReviewSessionScreen
                └── ProfileScreen → Logout: signOut + popUntil(isFirst)
```

- **AuthGate:** พอ Firebase แจ้งว่ามี user ก็สลับหน้าเอง เปิดแอปใหม่ก็ยังล็อกอินอยู่
- **`pushReplacement` จากหน้าอ่านไปหน้าสรุป:** ย้อนกลับไปดูบทความไม่ได้ ตรงกับหลัก Active Recall
- **RouteObserver:** Home รู้ว่าถูกกลับมาแสดง จึงเล่น effect ตัวเลขใหม่ได้

## 5. การทำงานแต่ละฟีเจอร์

### ธีมและภาษา

- **ธีม:** ยังไม่ล็อกอิน = ตามเครื่อง, ล็อกอินแล้ว = ตามค่าที่ผู้ใช้ตั้ง
- **ภาษามี 3 ค่า:** ภาษาแอป, ภาษาบทความ, ภาษาเสียงอ่าน (`AUTO` = ตามภาษาบทความ)
- เปลี่ยนภาษาแล้วถามว่าจะรีสตาร์ตไหม iOS ไม่ให้แอปปิดตัวเองแล้วเปิดใหม่ จึงรีสตาร์ตจากภายในด้วย `AppRestarter` (เปลี่ยน Key ชั้นบนสุด)
- ข้อความในหน้าจอใช้ `context.l10n.xxx` ส่วนใน service ซึ่งไม่มี context ใช้ `tr.xxx`

### สุ่มบทความ

- **ทุกหมวด:** `generator=random`
- **หมวดยอดฮิต 5 หมวด:** `list=search` + `articletopic:` + `srsort=random`
- **ค้นเอง:** `list=search` + `srsort=relevance` แล้วสุ่มใน 50 เรื่องที่ตรงที่สุด
- **ไม่สุ่มซ้ำ:** ทุกบันทึกเก็บ `source` + `language` + `pageId` รวมเป็น `readKey` แล้วตัดออกจากผู้สมัคร
- **อ่านครบหมวด:** โยน `TopicExhaustedException` กลับ Home พร้อมข้อความ
- **เพิ่มแหล่งบทความใหม่:** เขียน class ที่ implements `ArticleSource` แล้วใส่ใน `ArticleSources.all` หน้าจอไม่ต้องแก้

### หน้าอ่าน

- **เวลา:** `_baseElapsed + Stopwatch` = เวลาอ่านรวม ส่วน `Timer.periodic` แค่สั่งวาดจอทุกวินาที
- **พักและอ่านต่อ:** `ReadingSession` เก็บบทความ เวลา และร่างสรุปเป็น JSON ใน key `activeSession_<uid>` บันทึกทุก 10 วินาที ตอนออกจากหน้า และตอนสลับแอป
- **ล็อก:** ระหว่างมีเรื่องค้าง จะสุ่มเรื่องใหม่ไม่ได้ การ์ดอ่านต่อขึ้นแทนการ์ดสุ่ม
- **เสียงอ่าน:** `DeviceTtsService` อ่านทีละย่อหน้า ปรับความเร็ว 0.75–1.5 เท่า ไฮไลต์และเลื่อนจอตาม
- **โน้ตชวนนึก:** AI ตั้งคำถาม 1 ข้อจากบทความ เก็บในเซสชัน แล้วบันทึกลง Firestore เพื่อใช้ตอนทบทวน ถ้า AI ล่มใช้คำถามทั่วไปแทน
- **พื้นหลังโคมไฟ:** แสงตามนิ้วและ "หายใจ" ระหว่างจับเวลา วาดด้วย `CustomPainter` + `Ticker`
- **บุ๊กมาร์ก:** เก็บในเครื่องแยกตามบัญชี ยังไม่มีหน้ารายการ

### AI ให้คะแนน

AI ไม่ได้เดาคะแนนเอง แต่ทำ 3 อย่าง: ระบุประเด็นสำคัญ 6–8 ข้อ, ตรวจว่าแต่ละข้อมีในสรุปไหม, และคัดข้อความจากสรุปมาเป็นหลักฐาน จากนั้นแอปคำนวณเองใน `SlmService.scoreOf()`

- ประเด็น core หนักเป็น 2 เท่าของ detail
- ครอบคลุมและหาหลักฐานเจอในสรุป = เต็ม, หาหลักฐานไม่เจอ = ครึ่งเดียว
- ข้อมูลผิดหักข้อละ 10 สูงสุด 30
- ใช้ `temperature: 0` เพื่อให้ผลคงที่

ระดับคะแนน: 80 ขึ้นไป = จำได้แม่น, 60–79 = จำได้ดี, ต่ำกว่า 60 = ควรทบทวน (สีอำพัน ไม่ใช่สีแดง เพราะคะแนนต่ำแปลว่าควรอ่านซ้ำ ไม่ใช่ความผิดพลาด)

ตอน AI ล่ม ข้อความที่พิมพ์ยังอยู่ครบ ผู้ใช้ลองใหม่หรือบันทึกแบบไม่มีคะแนนได้

### ทบทวนแบบกล่องเลื่อนขั้น (Leitner)

โค้ดอยู่ที่ `models/review_schedule.dart`

- มี 5 กล่อง ทบทวนทุก 1 / 3 / 7 / 14 / 30 วัน บทความใหม่ครบกำหนดครั้งแรกวันถัดไป
- ให้คะแนนตัวเอง: ลืม → กล่อง 1, ยาก → กล่องเดิม, ดี → ขึ้น 1 กล่อง, ง่าย → ขึ้น 2 กล่อง
- เรียงคิว: เลยกำหนดนานสุดก่อน แล้วกล่องต่ำก่อน
- "ทบทวนสำเร็จ %" = ครั้งที่ตอบดีหรือง่าย ÷ ครั้งที่ทบทวนทั้งหมด

### สถิติ

โค้ดอยู่ที่ `models/period_stats.dart` และ `widgets/charts.dart` คำนวณจากประวัติในเครื่องทั้งหมด ไม่เก็บสถิติแยกใน Firestore

- เลือกช่วง 7 วัน / 30 วัน / ทั้งหมด และเทียบกับช่วงก่อนหน้าที่ยาวเท่ากัน
- กราฟเวลาอ่าน (เกิน 60 วันรวมเป็นรายสัปดาห์), คะแนนตามเวลา, ปฏิทิน 12 สัปดาห์, หมวดที่อ่าน
- ทุกกราฟสลับเป็นตารางได้ และมีคำอธิบายให้โปรแกรมอ่านหน้าจอ

### บัญชี

- **ตั้งค่าเริ่มต้น:** อ่าน `users/{uid}` แล้วไม่พบเอกสาร = ผู้ใช้ใหม่ จึงเปิด Onboarding
- **รูปโปรไฟล์:** ตัวละคร 5 แบบในแอป หรือรูปตัวเองที่ย่อเป็น 300×300 แล้วเก็บเป็น base64
- **ลืมรหัสผ่าน:** Firebase ส่งอีเมล ข้อความในแอปเขียนกลางๆ เพื่อไม่บอกว่าอีเมลไหนมีบัญชี
- **ล็อกอิน Google:** ใช้ `signInWithProvider` ของ Firebase ไม่ใช้แพ็กเกจ `google_sign_in` เพราะไลบรารี iOS ของมันเข้ากับ Firebase iOS 13 ไม่ได้ ต้องเปิด Google ใน Firebase Console ก่อนจึงใช้กับโปรเจกต์จริงได้
- **ปุ่ม Apple:** แสดงไว้เฉยๆ แตะแล้วขึ้นว่าเร็วๆ นี้
- **ลบบัญชี** (`services/account_service.dart`) หยุดทันทีถ้าขั้นไหนพลาด:
  1. ยืนยันตัวตน (รหัสผ่าน หรือ Google)
  2. ลบโปรไฟล์ `users/{uid}`
  3. ลบ `study_logs` ทีละชุด
  4. ลบบัญชี Firebase
  5. ล้างข้อมูลของบัญชีนี้ในเครื่อง

### การเคลื่อนไหวและการเข้าถึง

- ค่าทั้งหมดอยู่ใน `core/motion.dart`: เปลี่ยนหน้า 450 ms, การ์ดปรากฏ 500 ms, curve แบบเร็วต้นช้าปลาย
- เปิด Reduce Motion ในเครื่อง = effect ตกแต่งปิดทั้งหมด หน้าเปิดแอปเหลือโลโก้นิ่ง ไม่กะพริบ ไม่มีเสียง
- ไฟกะพริบหลังติดแล้วไม่ต่ำกว่า 30% ไม่เกิน 2 ครั้งต่อวินาที เพื่อความปลอดภัยต่อผู้ไวต่อแสง
- รองรับตัวอักษรใหญ่ 3 เท่า และมี Semantics สำหรับโปรแกรมอ่านหน้าจอ

## 6. เส้นทางโค้ด: กดแล้วเกิดอะไรขึ้น

### กดสุ่มบทความ

1. `widgets/start_session_sheet.dart`: เลือกหมวดหรือพิมพ์คำค้น
2. `reading_screen.dart` → `_loadArticle()` เรียก `_source.fetchRandomArticle(...)`
3. `wikipedia_source.dart`: สุ่มตามประเภทหมวด แล้วตัดเรื่องที่อ่านแล้ว
4. `_fetchContent()` ขอ `prop=extracts|info|pageimages`
5. `cleanExtractWithHeadings()` ตัดเทมเพลตและส่วนอ้างอิง
6. ได้ `Article` แล้ว `SessionService.save()` บันทึกทันที และเริ่มจับเวลา
7. `_loadRecallQuestion()` ให้ AI ตั้งคำถาม

### กดประเมินและบันทึก

1. `summary_screen.dart` → `_evaluateAndSave()`: ตรวจฟอร์ม (อย่างน้อย 50 ตัวอักษร)
2. `slm_service.dart` → `evaluate()` → `_chat()`: POST ไป Groq, timeout 30 วินาที, โดน 429 แล้วรอไม่เกิน 10 วินาทีและลองใหม่ 1 ครั้ง
3. `_parseEvaluation()`: ตัด `<think>` เอาเฉพาะช่วง `{...}` แล้วอ่าน JSON
4. `scoreOf()` คำนวณคะแนน
5. `_save()` → `StudyLogRepository.create()` หรือ `update()`
6. `SessionService.clear()` ล้างเรื่องที่ค้าง
7. Home ฟัง `watchLogs()` จึงเห็นการ์ดใหม่เองโดยไม่ต้องรีเฟรช

### ให้คะแนนตอนทบทวน

1. `review_session_screen.dart` → `_rate()`: `ReviewSchedule.nextBox()` หากล่องใหม่
2. `recordReview()` อัปเดต `reviewBox`, `nextReviewAt`, `lastReviewedAt`
3. นับครั้งด้วย `FieldValue.increment` ให้เซิร์ฟเวอร์บวก ไม่ทับกันถ้ามี 2 เครื่อง

## 8. งาน Asynchronous

| จุด | สิ่งที่รอ | ระหว่างรอ / ตอนผิดพลาด |
|---|---|---|
| `main()` | `.env`, SharedPreferences, Firebase | ทำก่อน `runApp`, Firebase พังแสดงหน้า error |
| Login / สมัคร | Firebase Auth | ปุ่ม disable + spinner, แปลง error เป็นข้อความตามภาษา |
| Home | Firestore stream, เซสชัน, โปรไฟล์, คำทักทาย AI | `StreamBuilder`, ใช้ข้อความสำรองระหว่างรอ |
| อ่าน | Wikipedia, บันทึกเซสชัน, คำถาม AI, TTS | ข้อความรอโหลด, timeout, ลองใหม่ได้ |
| สรุป | Groq → Firestore → ล้างเซสชัน | ปุ่มบอกสถานะ, AI ล่มบันทึกไว้ก่อนได้ |
| ทบทวน | `recordReview()` | SnackBar เมื่อล้มเหลว ให้คะแนนใหม่ได้ |
| ลบบัญชี | ยืนยันตัวตน → Firestore → Auth | error ขึ้นในกล่อง ลองใหม่ได้ |

**กฎที่ใช้ทุกที่:** ครอบ `await` ภายนอกด้วย `try / on AppException`, ใส่ `.timeout(...)`, เช็ก `mounted` หลัง `await`, และ `dispose()` ปิด Timer / Ticker / Controller / TTS

**Future vs Stream:** Future ให้ผลครั้งเดียว เช่น Login หรือบันทึก ส่วน Stream ให้ผลต่อเนื่อง เช่น สถานะล็อกอิน และรายการใน Firestore

## 10. สคริปต์นำเสนอและสาธิต

ปรับตามเวลาที่ได้รับ ถ้าเวลาน้อยให้ทำเฉพาะข้อ 1–5

1. **ปัญหา:** "อ่านแล้วลืม เพราะอ่านผ่านๆ KEEP ให้ฝึก Active Recall คือนึกเองก่อน แล้วค่อยตรวจ"
2. **เปิดแอป:** ให้เห็นโลโก้ประกอบกับไฟกะพริบ แล้ว Login
3. **Home:** ชี้จำนวนวันติดกัน, เป้าหมายวันนี้, ประวัติ แล้วกดสุ่มบทความและเลือกหมวด
4. **อ่าน:** ชี้ Timer, คำถามชวนนึกจาก AI, กดฟังเสียง แล้วกด "อ่านจบแล้ว" พร้อมบอกว่าย้อนกลับไปดูบทความไม่ได้
5. **สรุป:** ลองพิมพ์สั้นเกินให้เห็น Validation แล้วเขียนจริง กดประเมิน ชี้คะแนนและประเด็นที่ขาด
6. **ทบทวน:** นึก → เฉลย → ให้คะแนน บอกว่าแต่ละปุ่มเลื่อนวันทบทวนอย่างไร
7. **สถิติและโปรไฟล์:** เปลี่ยนช่วงเวลา, สลับเป็นตาราง, เปลี่ยนภาษาหรือธีม
8. **โค้ด:** เปิด `slm_service.dart` ที่ `scoreOf()` และ `firestore.rules`
9. **สรุป:** ข้อจำกัดและสิ่งที่จะพัฒนาต่อ (ข้อ 12)

**เตรียมก่อนวันนำเสนอ:** ทำบัญชีที่มีข้อมูลหลายวัน เพื่อให้กราฟดูเต็ม, เปิด Simulator ไว้ก่อน, เช็กอินเทอร์เน็ต เพราะสุ่มบทความและ AI ต้องใช้เน็ต

## 11. คำถามที่อาจโดนถาม

**ทำไมใช้ Flutter?** เขียนครั้งเดียวได้ทั้ง iOS และ Android

**คะแนนมาจาก AI ใช่ไหม?** ไม่ทั้งหมด AI ตรวจรายประเด็นพร้อมหลักฐาน แล้วแอปคำนวณเองใน `scoreOf()` จึงตรวจย้อนได้

**ถ้า AI ให้คะแนนผิด?** ผู้ใช้เห็นรายการประเด็นและ Feedback แก้สรุปแล้วประเมินใหม่ได้

**ทำไมใช้ Groq ไม่ใช้ OpenAI?** มีโควตาฟรีและตอบเร็ว API เข้ากันได้กับ OpenAI จึงเปลี่ยนผู้ให้บริการได้ที่ `.env`

**Groq กับ Grok ต่างกันไหม?** Groq เป็นผู้ให้บริการรันโมเดลบน Cloud ส่วน Grok เป็นโมเดลของ xAI

**ทำไม Wikipedia ไม่ต้องใช้ key?** เป็น API สาธารณะ แต่ต้องระบุ User-Agent ซึ่งแอปส่งไปแล้ว ถ้ากดถี่จะได้ 429

**API key ปลอดภัยไหม?** ไม่เต็มที่ `.env` ไม่ขึ้น Git แต่ถูกฝังไปกับแอป แกะแล้วอ่านได้ ทางแก้จริงคือเรียกผ่าน backend ซึ่งอยู่นอกขอบเขตของวิชา

**Firebase config เป็นความลับไหม?** ไม่ ความปลอดภัยของข้อมูลมาจาก Security Rules

**ทำไมไม่ใช้ Firebase Storage?** โปรเจกต์ใหม่ต้องใช้แผน Blaze ที่ผูกบัตร รูปที่ย่อแล้วเล็กพอเก็บใน Firestore (เอกสารละไม่เกิน 1 MB)

**ทำไมไม่ใช้ Bloc หรือ Provider?** แอปยังเล็ก ค่าที่ใช้ร่วมมีไม่กี่ตัว `ValueNotifier` กับ `StreamBuilder` พอแล้ว

**ทำไมเรียงข้อมูลในแอป ไม่ใช้ `orderBy`?** `where` + `orderBy` คนละ field ต้องสร้าง Composite Index ข้อมูลต่อคนไม่เยอะ เรียงในแอปเร็วพอ

**ทำไมกดบันทึกซ้ำไม่เกิดเอกสารซ้ำ?** จอง ID ด้วย `doc().id` ก่อน แล้ว `set()` ซ้ำจะทับเอกสารเดิม

**`set(merge: true)` ต่างจาก `update()` อย่างไร?** `update()` ต้องมีเอกสารอยู่แล้ว ส่วน `set(merge: true)` สร้างให้ถ้ายังไม่มี และแก้เฉพาะ field ที่ส่ง

**`serverTimestamp()` คืออะไร?** ใช้เวลาเซิร์ฟเวอร์ให้ตรงกันทุกเครื่อง ระหว่างรอยืนยันเป็น null ชั่วคราว แอปจึงใช้เวลาปัจจุบันแทน

**ทำไมตรวจข้อมูลซ้ำใน Rules?** ไม่ควรเชื่อการตรวจฝั่งแอปอย่างเดียว

**เน็ตหลุดระหว่างอ่าน?** เซสชันอยู่ในเครื่องแล้ว อ่านต่อได้ ส่วนสุ่มหรือบันทึกจะแจ้ง error และลองใหม่ได้

**ทำไมใช้กล่องเลื่อนขั้น ไม่ใช้ FSRS?** อธิบายง่าย ทำเสร็จทันเวลา และไม่ต้องเรียก AI เพิ่ม ข้อมูลที่เก็บไว้ยังใช้ต่อยอดเป็น FSRS ได้

**มีการทดสอบอะไรบ้าง?** `flutter test` มี 116 ข้อ ทำงานออฟไลน์ โดยจำลอง Wikipedia และ Groq ส่วน `test/live` เรียก API จริงและเปิดด้วย `LIVE=1`

## 12. ข้อจำกัดที่ควรรู้

- ไม่มี backend เอง key ของ Groq จึงฝังในแอป และการลบบัญชีทำจากฝั่งแอป ไม่ใช่ Cloud Function
- Rules ของ `study_logs` ยังตรวจแค่ `userId` ไม่ตรวจรูปแบบ field
- ล็อกอิน Google ต้องเปิดใน Firebase Console ก่อน ตอนนี้ถ้าล้มเหลวแบบหน้าเว็บปิดเอง แอปยังไม่แจ้งผู้ใช้
- บุ๊กมาร์กอยู่ในเครื่อง ยังไม่มีหน้ารายการ และไม่ถูกลบตอน Logout
- ปุ่ม Apple เป็นปุ่มแสดงเฉยๆ ถ้าจะขึ้น App Store จริงต้องทำให้ใช้งานได้
- คุณภาพคะแนนขึ้นกับโมเดล และเสียงอ่านขึ้นกับเสียงที่มีในเครื่อง
- Wikipedia จำกัดอัตราการเรียก ถ้ากดถี่จะได้ 429
